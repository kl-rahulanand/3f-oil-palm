### Reviewer focus

- THE PREDICATE MUST BE RE-DERIVED, NOT ACCEPTED. Only the pinned batch ids may come from the browser. If the leaf key, the triples, the month range or the plant scope are read off the request, a crafted nodeKey widens a RAW-ROW read - the one place in this system that returns individual transaction lines. Check every field's provenance in the code, not in the DTO comment.
- UUIDs BEFORE SQL. The repository interpolates literals and SqlValidator is a post-check that does not make interpolation safe. If the request schema does not constrain every pinned id to a UUID, a client string reaches SQL construction. There is a required negative test; confirm it exercises the schema, not a hand-built repository call.
- COMPLETENESS, NOT VALIDITY. 'Every pinned id is a real actuals batch in range' is the wrong check and passes while footing silently breaks: a client that omits one YTD month narrows the read and the footer disagrees with the number that was clicked. The rule is one id per month in range that HAS a batch, and a refusal otherwise.
- THE BUDGET BATCH IS PART OF THE PIN, AND THERE ARE TWELVE OF THEM. Budget ingest writes a batch per workbook month, so FY-YTD provenance carries several budget ids; the outline is the one whose period equals the block's `to`, which is what mis-statement.service.ts itself reads (findByBudgetPeriod(resolution.period.to)). Resolving the leaf through the ACTIVE outline instead lets a budget re-upload make the drill read a different leaf's transactions with every actuals id correct.
- AUDIT BEFORE THE ROWS, AND IT MUST THROW. writeRequestEvent is fail-closed by construction; a try/catch around the drill's audit write turns the whole guarantee off. Verify by test that NO sap_transaction query is issued when the insert fails - not that an error was logged. The refusal filter must be scoped to this route and must not audit unauthenticated callers, or an anonymous caller can fill the audit table; and a refusal event must not echo the RESOLVED predicate back.
- FOOTING IS AN EQUALITY, NOT A TOLERANCE. debit and credit are numeric(18,2), so the statement's paise are these rows' paise summed; any test comparing rounded rupees, or allowing a delta, is asserting nothing. Money must cross the wire as a fixed-scale string - a JSON number loses paise.
- DATE-ONLY, NOT toISOString. postgres.adapter.ts serializes DATE through toISOString(), so east of UTC a month of 2026-07-01 comes back as 2026-06-30. This bit the statement already. The required test must set a non-UTC TZ; one that runs under UTC proves nothing.
- NO SUPPRESSION HERE, AND NO SUPPRESSION REMOVED ELSEWHERE. This read is the documented k-anon exception (0025). Wiring applyKSuppression into it is wrong; so is touching the aggregate paths that legitimately use it.
- THE FY-YTD PROOF CANNOT USE CLIENT DATA. The supplied extract is July only. A test claiming a multi-batch FY-YTD footing against the July batch is proving nothing - it needs the constructed multi-period fixture, and the evidence must say which proofs are fixture-based.
- A TEST THAT CI DOES NOT RUN IS NOT A TEST. New hermetic files must be added to backend/package.json test:hermetic AND tools/quality-gate.test.mjs; the new gated proof to test:warehouse-proof. Editing audit.service.ts also requires formatting it and dropping its .prettierignore entry (D-0006). And check the EXECUTED COUNT and testcase name in every artifact, never the exit code (D-0024, D-0031).
