### Reviewer focus

- The download must match the STATEMENT, not the selectors. Building the request from mutable filter state lets someone generate July, change a dropdown, download, and get a file that silently disagrees with the screen - on a financial document people forward. It is built from the resolved response's scope.
- A silent no-op is the worst outcome - worse than an error - because the person believes they have the file and walks away. constitution/07-exception-handling.md's one-clear-state rule already bit this exact view once, where a failure rendered ALONGSIDE the empty state.
- Media-type discipline: ONLY the exact xlsx type (parameters allowed) enters the save path. The unresolvable outcome is a 200 carrying JSON, and any other unexpected type is an error - a blob client that saves whatever arrived puts a corrupt .xlsx on someone's disk.
- The binary path must keep the CSRF bootstrap, cookie credentials and the one-shot 401 refresh. Dropping the refresh silently breaks the download for anyone whose access token just expired, which is the most ordinary case there is.
- The filename is the SERVER's: Content-Disposition is readable only because main.ts exposes it through CORS, and deriving it client-side would duplicate a grammar the server owns and let the two drift.
- Revoke the object URL, and assert it - a page people click repeatedly should not leak one per click.
- Design fidelity: the prototype's Download Excel is a SECONDARY button (white ground, emerald border and text) sharing Generate's height and radius. No theme token may be added or renamed - and tokens.test.ts does NOT prove that, since it compares only the files under frontend/src/theme: read the diff.
